# 私信任务详情 · 数据展示方案

## 一、问题

私信任务详情当前复用通用子任务表：账号列是随机昵称（USERNAMES），目标只有一个名字，看不到「究竟发了什么私信」。而私信任务的审计核心恰恰是：**谁（托管账号）→ 对谁（目标账号）→ 发了什么（原文＋译文）→ 什么时候 → 结果如何**，与「触达会话」的口径一致。

## 二、展示方案（仅私信任务生效，其它类型不变）

### 1. 子任务列表列（按阅读顺序）

| 列 | 内容 |
|---|---|
| 子任务ID | 沿用 `T-xxx-001` |
| 目标账号 | 头像 + 昵称 + `@handle`（对方社媒账号） |
| 平台 | 平台 chip（Facebook / Tiktok） |
| 私信内容 | 上行原文（外语，单行截断）+ 下行灰色「中文：译文」；悬浮 Tooltip 展示完整原文与译文 |
| 执行账号 | 平台字母标 + 托管账号名（取自账号列表真实账号，非假名） |
| 发送时间 | 实际执行时间；未发送显示预计时间并标注「预计」 |
| 任务结果 | 执行成功 / 执行失败 / `-` |
| 执行状态 | 待执行 / 执行中 / 已完成 / 已终止 |
| 操作 | 日志、终止（沿用现有能力） |

去掉私信任务下的「目标」（泛化人群标签）与「操作/动作」列——动作恒为「私信」，已在任务概要体现；原「预计/实际执行时间」两列合并为「发送时间」，避免横向过宽。

### 2. 数据生成（保持确定性 mock）

- **目标账号**：沿用 `REACH_TARGETS` 按平台的目标名池，补 `@handle`（由昵称派生）与头像（现有 realistic 头像轮转），同一子任务稳定不变。
- **私信内容**：取任务自身的 `draft.scriptSend`（外语原文）与 `draft.scriptZh`（中文），把 `{联系人名}` 替换为该子任务的目标昵称，`{我的公司}/{我的姓名}` 替换为执行账号所属租户/运营人。这样每条私信与任务设定的话术、语种、区域完全对应。
- **执行账号**：从任务的 `reachAccounts`（真实托管账号 ID）轮转取账号名与平台，和统计弹窗「按账号分布」的口径一致。
- **成败与时间**：完全沿用现有 `buildSubTasks` 的分配逻辑，统计卡片数字不变。

### 3. 筛选条件

私信任务下：保留「搜索（子任务ID / 目标账号 / 执行账号 / 私信内容）」「平台」「任务结果」「执行状态」，隐藏「动作」下拉（恒为私信）。

## 三、不改动

统计卡片口径、统计分布弹窗、任务日志、诊断中心、其它四种任务类型的详情表格均不变。
